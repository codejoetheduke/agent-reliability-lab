# Personal development security boundary

Provider tokens load only in Python from environment variables or an external user JSON file. The original key file is Git-ignored and denied by Vite. Credentials, authorization headers, private root IDs, and actual Notion content are excluded from source, frontend bundles, SQLite evaluation history, logs, and sample reports. The private credential file has restricted Windows permissions; this is not OS-backed credential-vault storage.

The API binds to loopback, validates Host headers, and permits an explicit CORS origin list. A fresh 256-bit supervisor nonce protects every operation except public health and API documentation. Native IPC exposes only the loopback URL and nonce; provider keys never cross that boundary. Browser development receives the nonce through supervised HTML. CORS alone is not authorization. The scheme does not protect against malware or processes with the same user's privileges. Port checking reduces accidental collisions but is not a complete process-identity or port-race defense.

Tauri grants no frontend filesystem, shell, or external opener capability. The shell plugin is registered only for Rust to start the fixed bundled backend; JavaScript has no shell permission. Production CSP limits connections to the local API and Tauri IPC, uses local fonts/assets, and excludes remote frames. MUI needs inline styles. Structured errors omit request values, headers, raw provider bodies, and stack traces; logs use fixed JSON events/codes. HTTP access logs are disabled by the launcher.

Pydantic rejects unknown fields and invalid inputs. Gemini or OpenAI receives question/evidence only after affirmative consent; `store:false` is requested with no tools or automatic fallback. This does not promise the provider has no operational retention. Accepted claims/citations must match supplied evidence. Source text is rendered as text, and embedded instructions cannot invoke task actions. Benchmarks use synthetic material only; no training or fine-tuning pipeline exists.

Notion uses selected fictional test roots and read-content permission. Containment checks, fixed hosts, pagination/size budgets, and bounded retries constrain reads. Linked outside pages and arbitrary downloads are excluded. No Notion mutation exists. Mock create/update actions use separate local tables, confirmed immutable proposals, rollback, idempotency keys, optimistic versions, and explicit failure/retry states.

History defaults to ignored `.local/history.sqlite3`. Run History provides confirmed deletion and refuses during active evaluations. Mock task/proposal reset is separate and confirmed. Notion uses a bounded memory cache with explicit clearing; closing the process clears it. Source/conversation state is discarded on section/source changes. SQLite deletion is logical, not forensic secure erasure; backups and exported reports require separate management. No automatic telemetry or hidden workspace upload exists.

Installed releases bundle and supervise Python with a protected readiness probe and ephemeral port. Before public distribution: further strengthen authenticated process binding, use an OS credential vault, implement supported public Notion OAuth/revocation, review privacy/data-use permissions, sign binaries/updates, audit dependencies/capabilities, and test adversarial local clients and injection cases. Internal workspace tokens are unsuitable as public desktop authentication. Functional tests are not a comprehensive penetration test.
